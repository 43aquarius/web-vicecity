# 六分片部署提示词 · 总览与部署顺序

> **用途**：把 1.08 GB 游戏归档切成六段、分摊到六台中继，主站退化为纯兜底。
> 代码仓库 `43aquarius/web-vicecity`：六个分片分支（relay-a / relay-a2 / relay-b / relay-b2 / relay-c / relay-d）+ `main`（主站）。
> 每台中继一段独立提示词——**打开对应服务器的 AI 编程助手，把该分片的提示词整段粘贴给它**即可。

## 推荐部署顺序（分阶段，收益最大化）

**第一阶段（收益 ~90%）：只上 c + d。**
初次进入游戏的 62.7 MB 引擎数据 100% 落在 c/d 的区间内、由两台并行各拉一半（c/d 边界 987212548 特意切在引擎大文件 data.br 正中）。两台验证通过后，把两个地址发回主站侧对话，主站配置先切四分片（a、b 维持旧整段区间不动）：

```text
a=https://vicecity-relay-a.space-z.ai/revcdos.bin:0-361454906,b=https://vicecity-relay-b.space-z.ai/revcdos.bin:361454906-722909812,c=<c的地址>:722909812-987212548,d=<d的地址>:987212548-1084364719
```

**第二阶段（锦上添花）：上 a2 + b2**，摊薄进游戏后的 3.1 万个随机小文件访问。

**第三阶段（收尾）：重做 relay-a + 验证 relay-b**，六分片正式成型，主站切完整六分片配置：

```text
a=https://vicecity-relay-a.space-z.ai/revcdos.bin:0-180727453,a2=https://vicecity-relay-a2.space-z.ai/revcdos.bin:180727453-361454906,b=https://vicecity-relay-b.space-z.ai/revcdos.bin:361454906-542182359,b2=https://vicecity-relay-b2.space-z.ai/revcdos.bin:542182359-722909812,c=https://vicecity-relay-c.space-z.ai/revcdos.bin:722909812-987212548,d=https://vicecity-relay-d.space-z.ai/revcdos.bin:987212548-1084364719
```

> 六台部署互不依赖。赶时间可以六台并行全上，再把六个地址一起发回来，直接切完整六分片配置。
> 实际域名与模板不同没关系——发实际地址即可，主站配置以实际为准。

## 每台部署完成后要汇报什么

1. 最终对外地址（形如 `https://vicecity-relay-c.space-z.ai/revcdos.bin`，含 `/revcdos.bin` 路径）
2. `/healthz` 完整 JSON（确认 `state=ready` + `part` 区间正确）
3. 一条 206 验证的响应头（或截图）

把汇报发回**主站侧的 AI 对话**即可——由主站侧更新 `relay.config.json` 并指导重新发布。
